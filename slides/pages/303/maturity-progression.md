# Engineering Maturity Progression

```mermaid
graph LR
    A[Chaotic] --> B[Individual] --> C[Team-Shaped] --> D[Governed] --> E[Agentic] --> F[Spec-Driven] --> G[Operationalized]
    
    style A fill:#fee2e2
    style B fill:#fed7aa
    style C fill:#fef3c7
    style D fill:#d1fae5
    style E fill:#dbeafe
    style F fill:#e0e7ff
    style G fill:#ede9fe
```

<div class="grid grid-cols-4 gap-3 mt-4 text-xs">

<div class="p-2 rounded border">
<strong>Chaotic → Individual</strong><br/>
Autocomplete, inline prompting, experimentation. No governance. Module 101–102.
</div>

<div class="p-2 rounded border">
<strong>Team-Shaped → Governed</strong><br/>
Instruction files, ADRs, conventions, reusable patterns. Module 201–203.
</div>

<div class="p-2 rounded border">
<strong>Agentic → Spec-Driven</strong><br/>
Delegated workflows, planning-first, validation loops. Module 202, 301–302.
</div>

<div class="p-2 rounded border">
<strong>Operationalized</strong><br/>
Governance, visibility, budgets, rollout, platform enablement. Module 303.
</div>

</div>

<div class="mt-4 text-sm text-center opacity-70">

Most organizations have teams at different stages simultaneously. That's normal. The goal is progressive evolution, not uniform compliance.

</div>
